# 论文原图交付协议（必读）

只要提到具体论文的 Figure、Table 截图或公式原图，就先执行本协议。

**图像交付成功的唯一标准：用户可见的消息中实际渲染了经确认的论文原图或截图。** 图片名、URL、引用来源、图片路径、Python 打印出的文件路径，以及“图1左/中/右”文字描述都不是图像交付。不得说“请看上图/图已发出”，除非确实调用了用户可见图像输出工具并得到图像结果。

## 1. 获得真实图像像素

1. 已获得 PDF：使用原有 extract_figures.py；检查 figures/index.json 与 _contact.png。调用 prepare_figure.py <paper-dir> 1 从索引定位图像；自动裁剪失败时从 PDF 原页手动裁剪。每张图都要肉眼查看真实像素。
2. 作者官网或论文在线图片：仅当图片与当前论文及 Figure 编号精确对应时，使用真正的图片资源或可下载图像字节。单独的项目页链接不能替代图片。
3. 只有论文链接/搜索摘要而没有 PDF 图片字节时：尝试网页/PDF 工具获取原文图片。不可仅根据 caption 伪造图像，也不能用 image generation 重新画“论文原图”。

## 2. 生成可发图片文件（不是展示）

示例：python <skill>/scripts/prepare_figure.py <paper-dir> 1

该脚本回传 image_path、page、caption、scope、ready_to_display。ready_to_display=true **只代表本地 PNG 已存在，绝不代表图片已发出**。

mode=整页 或自动裁图不准确时，必须检查 PDF 原页，可用 --page N --bbox X0 Y0 X1 Y1 重新裁图。不知道准确边界时可以给实际 PDF 页预览，但标注为“第N页截图，尚非精确 Figure 裁图”。

## 3. 实际在聊天里显示图片（不可跳过）

必须调用能产生**用户可见图片消息**的工具、图片组件或附件功能，而不是仅输出图片路径。在支持向用户展示图像结果的 Python 工具中，可以执行：

    from IPython.display import display, Image
    display(Image(filename="/经过验证的真实图片路径/fig-01.png"))

此例只适用于 Python 工具的图像输出真的对用户可见的会话；私有 analysis Python 工具即使运行代码也不等于交付图片。也可以使用平台原生图片输出组件，但必须引用已经核实的具体图片，不能只用网页引用组件。

**严格顺序：先实际发图 → 再标注 Figure N 和来源 → 再按左/中/右讲解。** 若图片输出失败，先重试原 PDF 页面图像/裁剪；仍无法内嵌时给已验证的 PNG 附件/下载链接，并明确告知“当前未能在消息中直接显示图片”。不能继续写“请看上图”。

## 4. 回复前核验

- 实际图片是否来自同一篇论文的同一版本？
- 是否肉眼检查了图像像素、边界、方位？
- 用户可见的消息里是否真的有图片（不是链接、路径、图注）？
- 若没有，是否明确标注未内嵌，并提供已验证的回退资源？

如果讲解依赖尚未显示的关键图，请先处理缺图，再继续六阶段教学。将缺图状态记入 reading-state.json，而不是假装发图成功。
